# Data Release: 242 generated, 233 scored

This note explains a deliberate discrepancy a reader will notice in the released
evaluation data: **the per-question spreadsheets contain 242 rows, but the paper
reports scores over 233 questions.** Nothing is hidden — the full data is shipped
intact and the 9-item difference is documented, flagged in-place, and reproducible
from a committed script. This is the transparent form of the exclusion; we keep all
242 rows precisely so the with/against-exclusion analyses can both be reproduced.

## The count chain

```
242  questions generated by the benchmark pipeline (Benchmark-Generator)
 −9  removed by a final expert item-by-item audit (see reasons below)
====
233  questions scored in the paper (all reported means, deltas, significance)
```

The audit ran **after** answers were generated and judged, so every model was run
on all 242 questions. The 9 audited-out items still appear in the raw answer and
judge sheets; they are simply excluded from scoring. The paper's headline numbers
are the **233-item** set; we verified (paper §5) that the full-242 and reduced-233
analyses agree on **every reported finding**, so the exclusion is a robustness
check, not a result-altering correction. Keeping all 242 rows is what lets a
reviewer reproduce *both* analyses and confirm that.

"Dangling source-text reference" means the question or its reference answer
presupposes source text that the closed-book model never sees, so it cannot be
answered fairly under our protocol.

## How the discrepancy is marked in the data

Every published **per-question** sheet carries an explicit boolean column so the
233-vs-242 split is self-documenting in-place — no cross-referencing required:

- **`excluded_from_scoring`** — `TRUE` for the 9 audited-out items, `FALSE`
  otherwise. Present in:
  - `NetBench-LLM/outputs/by_model/*/evaluations/answers/*.xlsx` (sheet `Answers`)
  - `NetBench-LLM/outputs/by_model/*/evaluations/judged/*.xlsx` (sheet `Judged`,
    both `_by_gpt-5.1` and `_by_gemini-3.5-flash` judges)

To reproduce the paper's scored set, drop the rows where
`excluded_from_scoring == TRUE` (or equivalently, the ids in
`analysis/excluded_items.csv`). The flag is a pure function of the question id and
is regenerated idempotently; if any sheet is regenerated, re-apply it.

## Important: in-file summaries and report sheets are over the full 242

These aggregate artifacts were produced by the evaluation pipeline **before** the
audit and therefore summarize all 242 questions. Their headline numbers will differ
slightly from the paper, by design:

- the `Summary` tab inside each `*_judged_*.xlsx`,
- `evaluations/reports/HPN_BENCHMARK_REPORT_v5.0_*.{md,xlsx}` and
  `hpn_benchmark_report_v5.0_*.xlsx`,
- `evaluations/adaptation_reports/*.xlsx`.

**The paper's numbers are not these.** The authoritative 233-scored tables are
regenerated from the per-question judge sheets with the exclusion applied:

```bash
analysis/.venv/bin/python analysis/aggregate_scores.py   # applies excluded_items.csv -> 233 scored
analysis/.venv/bin/python analysis/make_tables.py        # -> paper/tables/*.tex
analysis/.venv/bin/python analysis/make_figures.py       # -> paper/figures/*.pdf
```

Outputs of record (each committed; the paper traces to these):

- [`analysis/outputs/MASTER_RESULTS.md`](analysis/outputs/MASTER_RESULTS.md) — combined per-model/per-variant scores
- [`analysis/outputs/summary_by_variant.csv`](analysis/outputs/summary_by_variant.csv)
- [`analysis/outputs/significance*.csv`](analysis/outputs/) — paired tests (gpt-5.1 primary judge)
- [`analysis/outputs/HPN_JUDGE_AGREEMENT_gpt-5.1_vs_gemini-3.5-flash.*`](analysis/outputs/) — second-judge robustness check

## Judges

`gpt-5.1` is the **primary** judge; all reported numbers use it. `gemini-3.5-flash`
is a **second judge** run for robustness (rank correlation ρ=0.99 with the primary);
both judge sheets are released and both carry the `excluded_from_scoring` flag.
