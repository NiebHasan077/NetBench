# NetBench

A benchmark and an experimental framework for measuring how domain adaptation
changes what a language model knows about **high-performance networking** —
bulk data transfer, congestion control, bottleneck diagnosis, and the parameters
that govern them.

The repository holds three things: the **HPN-QA benchmark**, the **pipeline that
produced it** together with the adaptation and evaluation experiments run
against it, and the **analysis code that turns those results into every number
in the accompanying paper**.

```bash
make setup       # build the analysis environment from requirements.lock
make reproduce   # re-derive every reported number, then verify it matches
```

`make reproduce` is the central claim: from the judged outputs committed here,
every CSV, table, and figure behind the paper is regenerated by these scripts,
and the target exits non-zero if anything comes back different. It runs on every
push (`.github/workflows/reproduce.yml`).

That is the strongest of three claims this repository makes, and they are not
interchangeable — re-running the evaluation gives you close but not identical
numbers, and the paper corpus cannot be re-acquired at all.
**[REPRODUCING.md](REPRODUCING.md)** separates them, says what each needs, and
gives the cross-module runbook. Start there before attempting anything past
`make reproduce`.

## The benchmark

**HPN-QA v5.0** — 242 open-ended questions (233 scored), generated from 175
open-access publications and graded against a reference answer on correctness,
completeness, clarity, and conciseness.

```
NetBench-LLM/data/prompts/hpn_benchmark_v5.0.jsonl
```

Each item carries its source evidence quotes with DOI and licence, the outcome
of the three-model calibration ladder that assigns its difficulty, its
validation results, and a flag marking the 9 items excluded from scoring.

Read **[BENCHMARK_CARD.md](BENCHMARK_CARD.md)** before using it — composition,
field semantics, intended use, and known limitations.

## The experiment

8 open-weight models (1B–27B) across up to 8 adaptation variants — instruct
baseline, LoRA and full supervised fine-tuning, continued pre-training, and
retrieval — plus 3 frontier API baselines, all answering the identical items
under the identical protocol and scored by two independent LLM judges. A
two-expert human study validates the primary judge.

The design was fixed before the results were analysed and is recorded in
**[docs/STUDY_DESIGN.md](docs/STUDY_DESIGN.md)**, including the pre-registered
statistical protocol that `analysis/aggregate_scores.py` implements.

## The six modules

One data pipeline, six self-contained modules. Each has its own
`requirements.txt`, its own virtualenv, and its own README.

```
Collect-papers/       acquire open-access PDFs, deduplicate against a paperbase
   └─ Paper2Corpus/      PDF -> cleaned JSON text corpus
        ├─ Benchmark-Generator/   corpus -> the HPN-QA benchmark
        ├─ Instruct-FTD/          corpus -> instruction fine-tuning data
        └─ NetBench-LLM/ + NetBench-RAG/
                              adaptation, generation, judging, profiling
                                 └─ analysis/   -> aggregated CSVs, tables, figures
```

`NetBench-LLM/` is the direct pipeline (continued pre-training, fine-tuning,
LoRA, generation, profiling); `NetBench-RAG/` is the retrieval-augmented
variant. Both run the same three-phase evaluation with identical judge prompts,
rubric, and output schema, so their results are directly comparable.

## What is not here

Source PDFs, the extracted text corpus, model weights, checkpoints, LoRA
adapters, and retrieval indexes are not redistributed. Checksums are recorded as
provenance, not as download links.

Weights, adapters, and indexes are regenerable from the released scripts. The
corpus is not: `Collect-papers` queries live scholarly indexes, so a run today
returns a different paper set than the one behind the recorded hash. Every
downstream artifact is conditioned on that corpus, which is why the analysis
layer starts from the committed judged outputs rather than from the corpus.
[REPRODUCING.md §4](REPRODUCING.md) sets out each limit and its cause.

Per-run source states are recorded as snapshot tags, but every run carries the
evidence status `recovered_from_artifact`: the experiments ran across three
compute sites with independently staged working copies, so a tag is a recovered
post-run state rather than a checkout captured at launch.
[PROVENANCE.md](PROVENANCE.md) sets out exactly how far that chain holds.
